# Crypto Price Tracker

REST API для отслеживания криптовалют, получения USD-котировок CoinMarketCap
и хранения истории цен в SQLite. Поддерживает добавление и удаление монет,
паузу отслеживания, ручное и автоматическое обновление цен.

Стек: Node.js 18+, TypeScript, Express, axios, SQLite с raw SQL, Jest и Supertest.
API описан в OpenAPI 3.0 и доступен через Swagger UI.

## Установка и запуск

Требуются Node.js 18+ и npm. Все команды выполняйте из корня проекта.
Пример ниже — для PowerShell; npm запускается через `npm.cmd`, поэтому
изменять политику выполнения скриптов Windows не требуется.
В Linux/macOS используйте `npm` вместо `npm.cmd`.

1. Установите зависимости из lockfile:

   ```powershell
   npm.cmd ci
   ```

2. Создайте `.env` файл в корне проекта по образцу [.env.example](.env.example)
   и заполните настройки:

   | Переменная | Назначение | По умолчанию |
   | --- | --- | --- |
   | `SERVICE_API_KEY` | Bearer-ключ для доступа к этому API | Обязателен |
   | `CMC_API_KEY` | Ключ CoinMarketCap, используется только сервером | Обязателен |
   | `PORT` | HTTP-порт | `3000` |
   | `DATABASE_PATH` | Путь к файлу SQLite | `./data/app.sqlite` |
   | `CMC_TIMEOUT_MS` | Таймаут запроса CoinMarketCap | `5000` |
   | `SYNC_INTERVAL_MS` | Пауза между фоновыми обновлениями | `60000` |
   | `SHUTDOWN_TIMEOUT_MS` | Максимальное ожидание при остановке | `10000` |

   Получите API key в [CoinMarketCap Developer Portal](https://pro.coinmarketcap.com/)
   и замените значение `CMC_API_KEY` в `.env`.
   Перед первым запуском нового проекта сгенерируйте `SERVICE_API_KEY`
   скриптом или задайте собственный ключ вручную в `.env`:

   ```powershell
   node scripts/generate-service-key.cjs
   ```

   Скрипт автоматически сгенерирует ключ и запишет его в переменную
   `SERVICE_API_KEY` в `.env`; посмотреть готовый ключ можно в этом файле.
   Если ключ уже задан вручную, запускать скрипт не требуется.
   Ключи должны быть разными и не содержать пробелов.

   Сервер автоматически читает `.env`; переменные окружения имеют приоритет.
   На плане CoinMarketCap Basic интервал 60 секунд подходит для короткой проверки.
   Для постоянной работы с одним пакетом монет рекомендуется
   `SYNC_INTERVAL_MS=300000`, чтобы укладываться в месячную квоту.
   Число монет и ручных обновлений также влияет на расход кредитов.

3. Соберите и запустите сервер:

   ```powershell
   npm.cmd run build
   npm.cmd start
   ```

Сервер по умолчанию доступен на `http://localhost:3000`.
Файл БД и таблицы создаются автоматически; данные сохраняются после перезапуска.
После изменения `.env` перезапустите сервер.

## API

Откройте [Swagger UI](http://localhost:3000/docs/) и в **Authorize** введите
`SERVICE_API_KEY` без префикса `Bearer`.
Полная спецификация: [docs/openapi.json](docs/openapi.json)
или [JSON через сервер](http://localhost:3000/openapi.json).
Если изменён `PORT`, замените его в адресах.

Базовый путь — `/api/v1`.
Все маршруты ниже требуют заголовок
`Authorization: Bearer <SERVICE_API_KEY>`.
В адресах используется числовой CoinMarketCap ID (UCID):
`1` — Bitcoin, `1027` — Ethereum.

| Метод | Путь после /api/v1 | Действие | Успех |
| --- | --- | --- | --- |
| POST | `/cryptocurrencies` | Добавить монету: `{"cmcId":1027}` | 201 |
| GET | `/cryptocurrencies` | Получить список монет | 200 |
| GET | `/cryptocurrencies/:cmcId` | Получить данные монеты | 200 |
| PATCH | `/cryptocurrencies/:cmcId` | Изменить отслеживание: `{"trackingEnabled":false}` или `true` | 200 |
| DELETE | `/cryptocurrencies/:cmcId` | Удалить монету вместе с историей | 204 |
| POST | `/cryptocurrencies/:cmcId/price/refresh` | Получить и сохранить новую цену; тело не требуется | 200 |
| GET | `/cryptocurrencies/:cmcId/price` | Прочитать последнюю сохранённую цену | 200 |
| GET | `/cryptocurrencies/:cmcId/history` | Получить историю цен | 200 |

Список и история поддерживают `limit` (1–100, по умолчанию 50) и
`offset` (по умолчанию 0).
История также поддерживает включительные границы `from` и `to`
в формате ISO 8601 с часовым поясом.
Ответ страницы содержит `items` и `pagination`.

Создание монеты сразу сохраняет её первую цену.
Активные монеты обновляются при запуске сервера и затем по таймеру.
При `trackingEnabled:false` фоновое обновление приостановлено,
но чтение и ручной refresh доступны.
GET-запросы читают БД и не расходуют квоту CoinMarketCap.

Ошибки возвращаются в формате `{"error":{"code":"...","message":"..."}}`:
400 — неверный запрос, 401 — неверный или отсутствующий ключ,
404 — монета или котировка не найдена, 409 — монета уже добавлена,
502 — ошибка провайдера, 503 — лимит CoinMarketCap,
504 — таймаут провайдера, 500 — внутренняя ошибка.

## Быстрая проверка

После запуска выполните в Swagger:

1. Добавьте Bitcoin (`{"cmcId":1}`) и Ethereum (`{"cmcId":1027}`) через POST;
   проверьте список монет через GET.
2. Прочитайте цену ETH, выполните ручной refresh и проверьте новый снимок в истории.
3. Через 65 секунд проверьте появление фонового снимка при стандартном интервале;
   установите `trackingEnabled:false` и убедитесь, что история перестала расти.
4. Перезапустите сервер и проверьте сохранность данных;
   удалите тестовую монету и убедитесь, что GET возвращает 404.

Для проверки на отдельной БД перед запуском в PowerShell задайте
`$env:DATABASE_PATH='./data/smoke.sqlite'`.
Создание, ручной refresh и фоновые обновления расходуют квоту CoinMarketCap.

Для просмотра графика откройте [локальную страницу](http://localhost:3000/viewer/),
введите `SERVICE_API_KEY`, UCID добавленной монеты и нажмите **Следить**.

## Тесты

```powershell
npm.cmd test
```

Тесты проверяют API, ошибки CoinMarketCap, запись в SQLite,
фоновые обновления и остановку сервера.
Они используют отдельные временные БД и mock CoinMarketCap,
не обращаются к внешнему API и не читают локальный `.env`.

## Docker

Альтернативный запуск требует Docker с Linux-контейнерами и Compose v2.
Сначала подготовьте `.env` по инструкции выше, затем выполните:

```powershell
docker compose up --build -d
docker compose logs --tail 50 tracker
docker compose stop
```

API доступен на `http://localhost:3000` или порту из `.env`.
SQLite хранится в постоянном volume `tracker-data`, отдельно от локальной БД;
обычный `docker compose down` сохраняет данные.
Сборка и запуск контейнера пока не проверены.

## Ограничения

Приложение рассчитано на один процесс и одну валюту — USD.
История накапливается с момента добавления монеты и не очищается автоматически.
При исчерпании квоты CoinMarketCap обновления временно приостанавливаются,
а сохранённые данные остаются доступны.
Цены хранятся как `number` / SQLite `REAL`.

Доступ к SQLite реализован через драйвер `sqlite3` без ORM;
`dotenv` обеспечивает загрузку настроек на Node.js 18.
В дереве зависимостей остаются предупреждения `npm audit`,
включая критическое предупреждение в цепочке установки `sqlite3`.

`.env`, файлы SQLite, `node_modules` и результаты сборки исключены из Git;
`.env.example` содержит только шаблон настроек.
